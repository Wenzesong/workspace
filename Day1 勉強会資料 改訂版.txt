② Vibe Coding と Agentic Engineering（5分）
================================================================

【Vibe Coding とは】

  「最近 AI がコードを書いてくれる時代になりました。
   Vibe Coding という言葉を聞いたことがありますか？」

  Vibe Coding とは：
    AI に任せて雰囲気でコードを作るスタイル
    2025年に急速に広まった開発手法

  メリット：
    ・速い（アイデアから動くものまでが爆速）
    ・敷居が低い（プログラミング知識がなくても作れる）

  問題：
    ・AI が生成したコードは「動く」
    ・でも本番障害のリスクが隠れている
    ・作った人がリスクを理解していない


【Vibe Coding の具体的な危険】

  例：
    「注文処理APIを作って」と AI に頼む
      ↓
    動くコードが生成される
      ↓
    でも以下のリスクが隠れている：

      @Transactional がない
        → 部分失敗時に注文データが壊れる（P0）

      Redis のキャッシュ更新漏れ
        → 古いデータが残り業務誤処理（P1）

      認可チェックがない
        → 他人の注文データが見える（P0）

  → 作った人はこれを知らない
  → テストも通っている
  → 本番で初めて発覚する


【Vibe Coding だけでは不十分な時代】

  ✅ Vibe Coding は便利なツールとして残る
  ❌ Vibe Coding だけで終わる開発は危険

  「AI がコードを作る量が増えるほど
   品質を確認する仕組みが必要になる」


----------------------------------------------------------------
Vibe Coding vs Agentic Engineering の違い
----------------------------------------------------------------

  Vibe Coding：
    AI を使って「作る」

  Agentic Engineering：
    AI を使って「設計・守る・管理する」

  具体的な違い：

  項目              Vibe Coding           Agentic Engineering
  --------------------------------------------------------
  目的              速く作る              品質・安全を守る
  AI の使い方       コード生成を依頼      AIシステムを設計する
  ゴール            動くものを作る        本番で壊れないものを作る
  品質保証          ない                  P0〜P3で体系的に管理
  スキル            プロンプトを書く      AIの役割・流れを設計する
  成果物            アプリ・コード        AIが動くシステム・仕組み
  リスク管理        属人的・不安定        体系的・再現性がある

  一言で言うと：

    Vibe Coding         = AI に頼んで作ってもらう
    Agentic Engineering = AI を使ったシステムを自分で設計する


【Agentic Engineering とは】

  AIエージェントを設計・構築・運用する技術。
  2025年最も注目されているスキルセットの一つ。

  核心となる考え方：

    ① Decomposition（分解）
       大きなタスクを小さな Agent に分ける

    ② Orchestration（統合）
       各 Agent の結果を統合する

    ③ Dynamic Routing（動的ルーティング）
       状況に応じて必要な Agent を選ぶ

    ④ Context Management（文脈管理）
       Agent が必要な情報だけを持つ

    ⑤ Evaluation（評価）
       出力品質を継続的に改善する


【このプラットフォームの位置づけ】

  「AI がコードを作る時代だからこそ
   AI がコードを安全かどうか確認する
   仕組みが必要です」

  Vibe Coding で作る  → Enterprise AI Review Platform で守る

  このプラットフォームは
  Agentic Engineering の考え方で設計された
  「守る側のシステム」です。


================================================================
③ システムで何ができるか（7分）
================================================================

【従来のレビューとの違い】

  従来のレビュー
    コードスタイル・命名・Linter
    → 表面的な問題しか見えない

  このシステム
    トランザクション不整合
    SQLインジェクション
    N+1問題
    デッドロックリスク
    → 本番障害につながる問題を検出


【リスクレベルで分類】

  P0：即時対応必須（本番障害・データ破壊）
  P1：リリース前に対応
  P2：次スプリントで対応
  P3：改善推奨


================================================================
④ 仕組みを一言で（5分）
================================================================

  ① source-code/new/ にコードを置く
          ↓
  ② review.ps1 を実行
          ↓
  ③ コードを自動スキャン
      @Transactional を検出 → transaction_skill を自動ロード
      RedisTemplate を検出  → redis_skill を自動ロード
          ↓
  ④ final_review_prompt.txt が生成される
          ↓
  ⑤ Claude に貼り付ける
          ↓
  ⑥ レビュー結果が出力される

  キーワード：「必要な知識だけを自動で組み合わせる」
  これが Agentic Engineering の実践です。

⑤ デモ（7分）
================================================================

【手順】

  1. source-code/new/ にサンプルコードを配置     （1分）
  2. review.ps1 を実行                           （2分）
  3. output/ に生成されたファイルを確認           （1分）
  4. final_review_prompt.txt を Claude に貼り付け （1分）
  5. P0・P1の検出結果を一緒に読む                （2分）


【見せどころ】

  ・P0が検出された瞬間
  ・「なぜこれが危険か」の説明がAIから出てくる瞬間
  ・影響範囲・修正推奨まで自動で出てくること
  ・Vibe Coding で作ったコードのリスクを
    Agentic Engineering で設計したシステムが検出する

================================================================
想定される質問と回答
================================================================


Q1. 既存のLinterやSonarQubeと何が違うの？
----------------------------------------------------------------

  Linter・SonarQube：
    構文・スタイル・既知のパターンを検出
    → ルールベース・固定的

  このシステム：
    コードの「意味」を理解して分析
    例：このトランザクション境界は
        高負荷時に接続枯渇を起こす
    → 文脈を理解した判断ができる
    → Vibe Coding で生成されたコードの
      見えないリスクを検出できる


Q2. AIの出力を信頼していいの？精度は？
----------------------------------------------------------------

  100%ではありません。

  ただし：
    ・見逃しを減らすための補助ツール
    ・P0・P1の指摘は必ず人間が確認する
    ・AIが間違えたらSkillを改善して精度を上げる

  「AIが決める」ではなく
  「AIが気づかせて人間が判断する」


Q3. 導入コストは？設定が大変では？
----------------------------------------------------------------

  ・PowerShell が動けば使える
  ・API Key は不要
  ・コードを置いてスクリプトを実行するだけ

  セットアップは5分以内です


Q4. 会社のコードを外部に送って大丈夫？
----------------------------------------------------------------

  このシステムはコードを外部サーバに送りません。

  ・review.ps1 はローカルでPromptを生成するだけ
  ・Claudeに貼り付けるかどうかは自分で判断できる
  ・社内ルールに従ってご使用ください

  ※ 社内にClaudeのEnterprise契約がある場合は
    そちらを使うことを推奨します


Q5. Java以外にも使えるの？
----------------------------------------------------------------

  対応しています：
    ・Java / Spring Boot
    ・C# / ASP.NET
    ・SQL
    ・Linux / Shell / Docker / Kubernetes

  -Language パラメータを変えるだけです


Q6. 自分たちで内容をカスタマイズできるの？
----------------------------------------------------------------

  できます。これが最大の特徴です。

  Skillファイル（.md）を編集するだけで
  自社固有のリスクパターンを追加できます。

  例：
  「うちの会社でよく起きるこのパターンを
   必ず検出してほしい」
  → custom_skill.md に追加するだけ

  詳しくは3日目に説明します


Q7. Vibe Coding と Agentic Engineering は
    対立するものですか？
----------------------------------------------------------------

  対立しません。

  Vibe Coding   → 速く作るための手段
  Agentic Engineering → 安全に守るための設計

  両方使うのが理想です。

  「AI でコードを作って
   AI で品質を確認する」

  これが2025年のスマートな開発スタイルです。
