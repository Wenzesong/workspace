================================================================
md ファイルとは何か
================================================================

  正式名称：Markdown（マークダウン）ファイル
  拡張子  ：.md

  シンプルな記号で構造を表現できる
  テキストファイルの一種。

  たとえば：

    # 見出し
    ## 中見出し
    - リスト項目
    **強調**
    ```code```

  これだけで構造化された文書が書ける。


================================================================
md と他のファイル形式の違い
================================================================


  txt ファイル（普通のテキスト）
    Purpose
    トランザクション分析
    Risk Pattern
    長時間トランザクション
    外部API呼び出し

    → どこからどこまでが何の説明か
      機械にも人間にも分かりにくい


  Word ファイル
    見た目は綺麗だが
    AIに渡す時は不向き
    → バイナリ形式・構造情報が複雑


  HTML ファイル
    構造化はできるが
    タグが多くて読みづらい
    <h1>Purpose</h1>
    <p>トランザクション分析</p>


  md ファイル
    # Purpose
    トランザクション分析

    # Risk Pattern
    - 長時間トランザクション
    - 外部API呼び出し

    → 人間にも機械にも読みやすい
    → 構造が明確


================================================================
なぜ AI とのやり取りに md を使うのか
================================================================


  理由1：AIが構造を理解しやすい
  --------------------------------

    AIは膨大な量の md ファイルで学習している
    （GitHub・技術ブログ・ドキュメント等）

    → AI にとって最も「読み慣れた」形式
    → 構造を正確に解釈できる
    → 指示の遵守率が高い


  理由2：人間も読みやすい
  --------------------------------

    プログラマーが日常的に使う形式
    READMEもmdで書かれる

    → 編集・レビューが楽
    → チームで共有しやすい
    → Git管理に最適


  理由3：軽量・シンプル
  --------------------------------

    純粋なテキストファイル
    → 容量が小さい
    → エディタで簡単に編集できる
    → AIに送る時もトークン効率が良い


  理由4：構造と内容を分離できる
  --------------------------------

    # で見出し
    - でリスト
    | で表
    ``` でコード

    → 一目で「これは見出し」「これは表」と
      AIが判断できる
    → 純テキストでは表現できない情報を伝えられる


================================================================
具体例：md vs 純テキスト
================================================================


  ◆ 純テキストの場合
  --------------------------------

    トランザクション分析の専門家として動作してください
    以下のリスクパターンを検出してください
    長時間トランザクション 外部API呼び出し ネストトランザクション
    レベルはP0からP3まで分類してください
    P0は本番障害 P1は高負荷時障害 P2は将来の影響です

    → AIが内容を読み取れるが
      構造が曖昧で誤解が生じやすい


  ◆ md の場合
  --------------------------------

    # Role
    トランザクション分析の専門家

    # Detect Pattern
    - 長時間トランザクション
    - 外部API呼び出し
    - ネストトランザクション

    # Risk Level
    | Level | 意味 |
    |---|---|
    | P0 | 本番障害 |
    | P1 | 高負荷時障害 |
    | P2 | 将来の影響 |

    → 構造が明確
    → AIが各セクションを正確に理解
    → 出力の品質が安定する


================================================================
あなたの設計で md を使う理由
================================================================


  Enterprise AI Review Platform の核心は
  「AIに必要な知識だけを渡す」こと。

  そのために：

    Skill = 専門知識
    Agent = 役割定義
    Prompt = タスク指示
    Template = 出力形式

  これらを全て md で書く理由：

    ① 動的に組み合わせやすい
       PowerShellでmdファイルを結合するだけで
       1つの大きなPromptが作れる

    ② バージョン管理しやすい
       Gitで履歴を追える
       「いつどのSkillが追加されたか」が分かる

    ③ チームで分担しやすい
       1ファイル1機能なので
       複数人で並行して書ける

    ④ AIが正確に理解できる
       上記の理由から
       md は AI 入力の最適解


================================================================
md ファイルの記号の主な役割
================================================================


  記号    用途              AI への意味
  --------------------------------------------------------
  #       見出し            セクションの境界を示す
  ##      中見出し          細分化された構造
  -       リスト            並列の項目
  |       テーブル          ルールの構造化
  ```     コードブロック    「これはコード」と認識
  **      太字              重要性の強調
  >       引用              参照・引用情報
