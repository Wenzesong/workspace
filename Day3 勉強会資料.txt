① 会社固有Skillの紹介（10分）
================================================================

【なぜ会社固有Skillが必要か】

  通用Skill（汎用）
    → 業界共通のリスクを検出
    → 誰でも知っているパターン

  会社固有Skill（custom）
    → 自社で実際に起きた障害パターンを検出
    → うちの会社だけが知っている知識
    → 精度が圧倒的に高い


【保存場所】

  ai-review/skills/custom/
    └── terasoluna_batch_sqlserver_skill.md   ← 既に作成済み
    └── （次の障害事例）_skill.md
    └── （次の障害事例）_skill.md


【作成済みの例：terasoluna_batch_sqlserver_skill.md】

  背景：
    TerasolunaBatch × SQL Server の組み合わせで
    トランザクションが長時間残存する障害が発生。
    Batch側はエラーなし（サイレント障害）。
    DB監視担当者が気づいて手動Killするまで
    誰も気づけなかった。

  このSkillが検出するもの：
    ・Taskletへの @Transactional 直接付与
    ・REQUIRES_NEW 伝播設定の誤用
    ・leak-detection-threshold 未設定
    ・catch内での RepeatStatus.FINISHED 返却
    ・SQL Server向け接続プール設定の漏れ

  重要な点：
    Oracle環境では再現しないため
    テストで発見できない障害パターン。
    このSkillがあれば
    コードレビュー段階で検出できる。


【新しい障害事例の追加方法】

  1. ai-review/skills/custom/ に新しい .md を作成
  2. ai-review/routing/risk_patterns.yaml に検出ルールを追加
  3. 以上

  → 障害が起きるたびにチームの知識が蓄積される

② Agent Team構想（10分）
================================================================

【現行フレームワークの限界】

  現行（review.ps1）：
    1回のPromptで全Agent・全Skillを一括分析
    → 広く浅くカバーできる
    → 重要リリース前には物足りない場合がある


【Agent Team とは】

  複数のAIエージェントが順番にリレーして
  前のエージェントの結果を引き継ぎながら
  深度を増していくレビュー方式。


【フロー】

  agent_team.ps1 を実行
          ↓
  Step1: Transaction Agent が分析
         → step1_result.txt に保存（手動）
          ↓
  Step2: Security Agent が
         Step1の結果を参照しながら分析
         → step2_result.txt に保存（手動）
          ↓
  Step3: Orchestrator が
         全Stepの結果を統合
         → final_report.md


【現行フレームワークとの使い分け】

  日常のレビュー       → review.ps1（現行）
  重要リリース前       → agent_team.ps1


【既存資産の流用】

  新規追加が必要なもの：
    ・agents/ のmd × 5ファイル
    ・prompts/agent_team/ のmd × 2ファイル
    ・agent_team.ps1
    ・build_step_prompt.ps1

  そのまま使えるもの（変更不要）：
    ・skills/ 全Skill
    ・templates/ 全Template
    ・platform/ 定義
    ・routing/ YAML
    ・detect_context.ps1
    ・build_prompt.ps1

③ チーム運用ルールの話し合い（10分）
================================================================

【提案するルール】

  ルール1：障害事例のSkill化
    本番障害が発生したら
    1週間以内に custom_skill.md を追加する
    担当：障害対応チーム

  ルール2：重要リリース前のレビュー
    本番リリース前は必ず review.ps1 を実行する
    P0が残っている場合はリリース不可

  ルール3：Skillの改善
    AIの指摘が間違っていた場合は
    該当するSkillを修正してPRを出す
    担当：気づいた人


【話し合いのテーマ】

  ① 誰がSkillを管理・更新するか
  ② レビュー結果をどこに保存・共有するか
  ③ P0が検出された場合のフローをどうするか
  ④ 次に追加したい会社固有のSkillはあるか


【このシステムの位置づけ】

  「作って終わり」ではなく
  「チームで育てる知識ベース」

  障害が起きるたびにSkillが増え
  レビュー精度が上がっていく。

  1年後には
  「うちの会社のコードを一番よく知るAI」
  になることが目標。


================================================================
想定される質問と回答
================================================================


Q1. Skillの内容が間違っていたらどうするの？
----------------------------------------------------------------

  該当するSkillのmdファイルを修正するだけです。

  例：
  「この指摘は誤検出だった」
    → skills/ の該当ファイルを修正
    → risk_patterns.yaml の検出条件を調整

  AIの精度はSkillの品質に依存するため
  チーム全員で改善していく文化が重要です。


Q2. Agent Teamはいつから使えるの？
----------------------------------------------------------------

  現在開発中です。

  現行の review.ps1 は今すぐ使えます。
  Agent Team は完成次第展開します。


Q3. このシステムを使ってレビューを省略できる？
----------------------------------------------------------------

  省略はできません。

  このシステムは：
  「人間のレビューを補助するツール」です。

  AIが気づかせて
  人間が最終判断する
  という使い方が正しいです。


Q4. ChatGPTでも使えるの？
----------------------------------------------------------------

  使えます。

  final_review_prompt.txt を
  ChatGPT（GPT-4o以上）に貼り付けても
  同様のレビューが受けられます。

  社内の利用規約に従って使用してください。


Q5. 他のプロジェクトにも展開できる？
----------------------------------------------------------------

  できます。

  フォルダをコピーして
  source-code/ にそのプロジェクトのコードを置けば
  すぐに使えます。

  会社固有Skill（custom/）は
  全プロジェクトで共用することを推奨します。
