Tier の仕組み 説明資料
================================================================


================================================================
Tier とは何か
================================================================

  Skill の「優先度・重要度」を表す数値。

  Tier 1 → 最重要・常にロード対象
  Tier 2 → コードの複雑さに応じてロード
  Tier 3 → 深度分析が必要な場合にロード

  コードがシンプルなほど低いTierのSkillだけロードし
  複雑なほど高いTierまでロードする。


================================================================
Tier を管理するファイル
================================================================

  【risk_patterns.yaml】
    各ルールに tier: の値を設定する
    → 実際の制御値

  【skill_routing_rules.yaml】
    Tierごとのロード上限数を設定する

  【skill.md の @tier:】
    人間向けのメモ・ドキュメント用途のみ
    実際の制御には使われない


================================================================
具体例：SQLのTier設計
================================================================

  SQL Skill は20個ある。
  全部ロードするとPromptが巨大になる。
  → Tier で必要なものだけ絞り込む。


  ----------------------------------------
  Tier 1（必須・常時ロード）
  ----------------------------------------

    sql_skill               基本的なSQLリスク
    transaction_skill       トランザクション
    locking_skill           ロック競合
    deadlock_skill          デッドロック
    rollback_skill          ロールバック
    consistency_skill       データ整合性
    sql_injection_skill     SQLインジェクション

    → どんなSQLコードでも必ず必要な知識


  ----------------------------------------
  Tier 2（コード依存・複雑な場合にロード）
  ----------------------------------------

    index_skill             インデックス設計
    query_optimization_skill クエリ最適化
    migration_skill         マイグレーション
    execution_plan_skill    実行計画
    slow_query_skill        スロークエリ
    connection_pool_skill   接続プール
    high_load_sql_skill     高負荷SQL
    batch_processing_skill  バッチ処理
    pagination_skill        ページネーション
    retry_consistency_skill リトライ整合性

    → ALTER TABLE / OFFSET / バッチ処理など
      特定のパターンが検出された場合に追加


  ----------------------------------------
  Tier 3（オプション・深度分析が必要な場合）
  ----------------------------------------

    join_optimization_skill JOIN最適化
    subquery_skill          サブクエリ
    aggregation_skill       集計・GROUP BY

    → 3テーブル以上のJOIN・相関サブクエリなど
      高度な分析が必要な場合のみ追加


================================================================
maxTier の決まり方
================================================================

  コードをスキャンして
  マッチしたルールの中で最も大きいtier値が
  maxTier になる。

  例：

    @Transactional を検出 → tier: 1 のルールにマッチ
    @KafkaListener を検出 → tier: 2 のルールにマッチ
    ALTER TABLE を検出    → tier: 2 のルールにマッチ

    → maxTier = 2
    → tier 2 以下のSkillがロード対象になる
    → tier 3 のSkillはロードされない


================================================================
skill_routing_rules.yaml の上限設定
================================================================

  max_skill_count_tier1: 10
  max_skill_count_tier2: 6
  max_skill_count_tier3: 3

  意味：
    maxTier = 1 の場合 → 最大10個までロード
    maxTier = 2 の場合 → 最大6個までロード
    maxTier = 3 の場合 → 最大3個までロード

  上限を超えた場合：
    risk_patterns.yaml に書いてある順番で
    先頭から上限数までロード
    残りは切り捨て

  → 重要なSkillほど risk_patterns.yaml の
    前に書くことが推奨


================================================================
重要な注意点
================================================================

  現在の実装では：

    maxTier = 2 の場合
    「tier 2 以下の全Skill」がロードされるのではなく
    「マッチしたルールの中でtier 2 以下のSkill」がロードされる

    つまり：
      マッチしなかったルールのSkillは
      tierに関係なくロードされない


  例：
    risk_patterns.yaml に10個のルールがある
    うち3個だけマッチした

    → マッチした3個のSkillだけがロード対象
    → マッチしなかった7個はロードされない
    → その3個の中でtier <= maxTier のものを絞り込む


================================================================
Tier 設計のメリット
================================================================

  シンプルなコード
    → maxTier = 1
    → 必須Skillだけロード
    → Promptサイズ：小・高速

  複雑なコード
    → maxTier = 2 or 3
    → より多くのSkillをロード
    → Promptサイズ：大・深度分析

  → コードの複雑さに応じて自動調整される
  → 余計なSkillをロードしないので
    Token効率とレビュー品質を両立できる


================================================================
まとめ
================================================================

  Tier とは：    Skillの優先度を表す数値（1〜3）
  設定場所：     risk_patterns.yaml の tier: の値
  上限管理：     skill_routing_rules.yaml
  maxTier：      マッチしたルールの中の最大tier値
  ロード対象：   マッチしたルール かつ tier <= maxTier
